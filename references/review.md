# 看片和修改

## 每一版交给用户之前，自己先查

```bash
python3 <skill>/scripts/contact_sheet.py mv-r1.mp4 --every 0.5 -o review/r1-sheet.jpg               # 全片每 0.5 秒一格，自己看一遍
python3 <skill>/scripts/contact_sheet.py mv-r1.mp4 --srt lyrics.srt -o review/r1-lyrics.jpg          # 每句歌词刚出来时的画面，格子下面写第几句、起止（不印歌词，对着 lyrics.srt 看）
python3 <skill>/scripts/video_rhythm.py mv-r1.mp4 --analysis song-analysis.json --plan 7.6-8.03,10.03,14.03   # 切点、不动的段、黑帧、卡不卡拍；--plan 写计划的转场：落点，或者「起-落」一段
python3 <skill>/scripts/contact_sheet.py mv-r1.mp4 --around 8.03,10.03,14.03 -o review/r1-cuts.jpg   # 每个转场前后 0.6 秒、每 0.1 秒一格，一行一个转场，红框是转场那一刻
python3 <skill>/scripts/contact_sheet.py mv-r1.mp4 --every 1 --guides douyin -o review/r1-safe.jpg   # 竖屏：每格画上抖音安全范围和歌词带；横屏用 --guides wide；歌词不在默认那条带上加 --lyric-band A-B
node <skill>/scripts/render_frames.mjs --page mv/index.html --lyric-check                           # 有逐字时间时：每个字开唱那一帧看不看得见（render.md「歌词上屏」）
node <skill>/scripts/render_frames.mjs --page mv/index.html --times 7.3,21.8,33.1,48.6 --out review/r1-any   # 随便挑几帧出 1920 的大图，看人物和构图
```

转场落点不用自己抄：模板把镜头表算成 `window.PLAN`，`render_frames.mjs` 开头打印的「页面的转场落点」直接贴。眨眼、收光这种中间合上再张开的，`--plan` 写整段「起-落」。只做歌的一段时，`contact_sheet.py --srt` 加 `--offset -<起点>`，其他的见 `render.md`「只做歌的一段」。接触表格子多会拆成几张：第一张就是 `-o` 的名字，后面是 `-02`、`-03`……，标题上写第几张、共几张，脚本结尾列出全部文件名，每张都要看。

**随便抽几帧看大图**：接触表一格只有 320 px，`video_rhythm.py` 也量不出「同一个构图反复出现」「人物是几何块拼的」这类毛病（两位评审靠 1920 的截图才找出来）。交片前随便挑 4–6 个时刻（别只挑转场和高光）用 `--times` 出 1920 的原图，一张张看：人物造型和比例、线和形精不精致、背景有没有层次，像不像一张专业插画。

**`video_rhythm.py` 量出来的怎么读**：它只量帧差，下面几类会量偏，要对着接触表、逐帧条看：
- 报「几乎不动」「大轮廓没动」，但其实在动：像素风只有小人在动（整格平移、单像素的小点）、海报式的静画面、浅色细线条（彩虹、水珠）、浮世绘和一笔画这种只有细线和纸在动的画风。真是静的，就让大块的东西动起来（见 `styles.md`「静的画风怎么过「大轮廓不动」」）；分镜里故意停住的段用 `--hold A-B` 标出来
- 报计划外切点、不到 1 秒的「镜头」，但其实是镜头里设计好的大动作（灯冲亮、纸件立起来、冲击波、卡在拍上的游戏事件）：用 `--inshot 时刻` 标出来，算计划内、不切开镜头
- 量不到切点、镜头数比分镜少：原地慢渐变、横向辊子刷版、浪慢慢刷过去、一台镜头连着推过去或甩过去的换景，都被算进同一个镜头里。和分镜对镜头数看它打印的「按 --plan 的落点分」那一行
- 「停稳」偏晚：同构图每拍重印、灯暗换幕这类，落位以后镜头里还在动的东西也算进去了；拼贴这类一拍一动的画风常报晚 0.3–0.45 秒，看逐帧条确认落位那一帧在不在拍上
- 量过了不等于不平淡：小动作（萤火虫、呼吸）就能让它量过，画面照样会被说平淡。平淡靠看接触表和试渲
- 合集、分屏里 MV 只占一块、旁边是不动的面板：整幅量会多报很多「不动」，用 `--crop` 只量 MV 那块（按这个视频的像素写，裁到画面外会直接报错）

**纯音乐（没有歌词）**：「每句歌词出来时画面演的就是这句」「歌词不挡脸」这两条不用查，换成按段查：每段（`analyze_song.py` 的分段、突然变化的点）的画面在演什么、和这段的情绪对不对得上；「副歌至少有一个镜头比主歌近」换成「最响、最满的那一段至少有一个镜头比前面安静的段近」，同样拿接触表比主角在画面里有多大。分镜按段落和乐句写（见 `storyboard.md`「纯音乐」）

要过的线：
- 没有连着 1 秒以上几乎不动的段（故意停住的一拍除外）。「几乎不动」看的是相隔 0.1 秒的两帧整个画面平均差多少：只有一个小角色在动的镜头也会被报，看接触表确认，世界里再加点一直在动的东西（雪、光点、云）
- 也没有连着 1 秒以上「大轮廓几乎没动」的段：线条一直在抖、纸纹在闪，但人和东西都没动、镜头只是很慢地推，看着还是幻灯片。笔刷、拼贴这类一秒抖 12 次的画风靠这一项查（「几乎不动」会被线条抖动骗过去）；分镜里写明了故意静下来的除外
- 切点都是你打算切的地方，`--plan` 报的「计划外」要一个个看；转场是有衔接的（逐帧条里看得出东西是动过去的）。甩镜、快推、收光会被量成挨着的一串，脚本按一处转场算，报一个范围
- 转场落在拍上：`--plan` 每个转场报一行「停稳」，比落点早 0.2 秒以上或者晚 0.3 秒以上的，看逐帧条确认是不是提前落位、拖拍（报「没量到」的也看逐帧条）。提前落位多半是 `ease.out` 收得太早（`transitions.md`「不用匀速」）
- 副歌至少有一个镜头比主歌近：拿接触表比一比主角在画面里有多大（`character.md`「够大」）
- 没有意外的黑帧：钻进黑暗、灯灭换场、收光、眨眼这些故意黑下去的一两帧除外，对照逐帧条确认是演出来的。第一帧、最后一帧不是一片空白或纯黑
- 每句歌词出来时，画面演的就是这句
- 角色的脸、手、道具没被歌词挡住，远处的东西没被挡住；竖屏的歌词和脸在 `storyboard.md`「竖屏」说的范围里
- 成片响度和原曲差 1 dB 以内（`finalize_audio.py` 打印的）

你看不了视频：节奏和动静以脚本量出来的数为准，不凭感觉说「已经很流畅」。告诉用户这一版的结果时，说清楚哪些量过、哪些你拿不准。

## 最常见的 5 个毛病

用户说了下面这些，照第三列「怎么查、怎么改」做。第二列是教程里给用户复制的话，用户原样发过来时也按第三列做（比如让你「用 ffmpeg 抽帧算帧差」，就跑 `video_rhythm.py`，不用自己写）。

| 毛病 | 发给 agent 的话 | 怎么查、怎么改 |
|---|---|---|
| 像幻灯片 | 画面动态不足，像幻灯片。先用 ffmpeg 每 0.5 秒抽帧、计算相邻帧差，找出静止段落，再让角色持续有动作、镜头保持缓慢运动，每句歌词安排一个清晰的主要动作，以中近景呈现。 | `video_rhythm.py` 的「几乎不动的段」和「大轮廓几乎没动的段」；角色一直有动作（呼吸、走、反应），姿势之间补间，镜头一直在慢慢动，世界里有东西在动 |
| 运镜晃 | 镜头运动过于频繁。每个镜头只保留一种缓慢运动：慢推、慢移或跟随角色。 | 0.25 秒一格的接触表看构图是不是一直在跳；去掉来回推拉、每拍缩放、镜头里的旋转（转场时一次性的旋转不算）；一个镜头里最多一次远近变化 |
| 表现力不够 | 情绪表现不足。情绪最强的段落改用近景，光线与色调随情绪变化。 | 情绪点推到近景（角色大约占画面高度 35–50%，竖屏再大一档，手机上看得清表情）；反应放大（吃惊、跳、塌下去）；按段加整体色调和光 |
| 道具不对 | 手持道具位置异常。道具须贴合手部，且不得遮挡面部。 | 道具按 `handAt()` 画；逐帧条看手、道具、脸的位置关系；物件照真实的样子动（船在水上划，不从天上飞） |
| 歌词没演出来 | 「（这句歌词）」的画面未能表达歌词含义，请换一种更直观的表现方式。 | 先问用户这句想表达什么；照 `storyboard.md` 的规矩重新想这句（拆成几步、用身体演、不靠小道具）；整体看不懂就回第 4 步重写故事 |

## 其他常见的

| 毛病 | 怎么改 |
|---|---|
| 东西凭空消失又出现、角色瞬移 | 照 `transitions.md`「不管哪种都要做到」：前后帧接上、出画入画方向对上、消失要演出来 |
| 硬切、整屏叠化、转场看着僵 | 换成推拉、甩镜、前景扫过、画面里的东西自己变，按 `transitions.md`「按歌里的位置挑」换手法；照「在代码里怎么接」：转场那几拍两个镜头都画、拍前起步拍上落位、不用匀速 |
| 歌词对不上 | `--srt` 那张接触表找出偏的那几句；时间以 `lyrics.srt` 为准，错了让用户改 srt 再重转 `lyrics.js` |
| 声音变小了 | `finalize_audio.py` |
| 某段拖沓 | 过场一个画面一般 2 秒左右就够（再长观众就在等），里面要有一件看得懂的事 |

## 改的规矩

- 交给用户的每一版存一个新文件（`mv-r2.mp4`…），旧的留着；告诉用户改了什么、在哪几秒。还没交出去的，自检时返工直接覆盖这一版
- 只重渲改过的段（`render_frames.mjs --from 12 --to 18 --force`），再不带 `--from --to` 跑一遍 `--encode render.mp4` 接整片（渲好的帧会跳过；带着 `--from --to` 只接那一段）、`finalize_audio.py` 配一遍。改了 `character.js`、调色板这类共用的东西，用到它的镜头都要 `--force`，旧帧不会自己作废
- 每一版都重跑上面的自检
- 用户说「看不出 X」：先问清楚是表现方式不够直观，还是剧情本身不对。剧情不对就回第 4 步整个重写
